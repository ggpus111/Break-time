# 쉬는시간

**대동제 부스 줄서기를 없애는 QR 주문 웹앱.**
폰으로 QR을 찍으면 메뉴가 뜨고, 담아서 주문을 넣으면 번호표가 나오고, 부스에서 만드는
동안 상태가 실시간으로 바뀌다가 다 되면 소리와 진동으로 알려줍니다. 부스 운영자 쪽에는
주문을 처리하고 메뉴 · 재고 · 영업 상태를 관리하는 화면이 따로 있습니다.

스마트콘텐츠학과 '쉬는시간' 부스가 실제로 쓰기 위해 만든 프로젝트이고, 학과 이름 · 메뉴 ·
계좌 같은 건 전부 화면에서 바꿀 수 있게 만들어서 다른 부스도 그대로 가져다 쓸 수 있습니다.

---

## 왜 만들었나

축제 부스는 보통 종이에 손으로 번호를 적거나, 주문받는 사람과 결제 확인하는 사람이 따로
없어서 줄이 엉키기 쉽습니다. 이 프로젝트는 그 과정을 QR 하나로 대체합니다 — 손님은 줄을
서는 대신 자기 폰에서 주문하고 번호표를 받아 기다리고, 운영자는 들어오는 주문을 한 화면에서
순서대로 처리합니다. 서버를 따로 두지 않고, 프론트엔드 정적 파일과 Supabase만으로 구성해서
누구나 무료로 복사해 쓸 수 있게 만들었습니다.

## 화면 둘러보기

### 손님 화면 (`index.html`)
QR을 찍으면 바로 열리는 페이지입니다.

- 교시별로 나뉜 메뉴판, 담기/빼기 스테퍼, 품절 · 준비중 자동 표시
- 쫀드기 튀김 · 슈감자처럼 **시즈닝을 하나 골라야 하는 메뉴**는 옵션마다 담기 버튼이 따로
  붙어서 실수 없이 고를 수 있음
- 계좌이체 / 현금 중 선택, 합계는 항상 서버가 계산 (손님이 금액을 조작할 수 없음)
- 번호표 화면에서 접수 → 만드는 중 → 나왔어요 상태가 실시간으로 바뀌고, **내 앞에 몇 명
  남았는지**도 같이 보여줌
- 화면을 나가도 **내 번호표** 목록에 남아 있고, 상태가 "나왔어요"로 바뀌는 순간 소리와
  진동으로 알려줌 (알림 권한이나 팝업 없이, 탭이 열려 있는 동안 동작)
- 같은 주문을 실수로 두 번 넣으려 하면 한 번 확인을 받는 중복 방지 장치

### 관리자 화면 (`gyomusil-7x4m.html`, "교무실")
부스 운영진만 아는 별도 주소로 들어가는 페이지입니다. 손님 화면 어디에도 이 주소로 가는
링크는 없습니다.

- Supabase Auth로 로그인, 등록된 관리자 이메일만 통과
- 새 주문이 들어올 때마다 종소리가 울리는 실시간 주문판
- 입금 확인 → 만들기 시작 → 호출 → 전달 완료를 버튼 하나로 넘기는 상태 관리
- 메뉴 이름 · 가격 · 품절 · 시즈닝 옵션을 코드 수정 없이 화면에서 바로 편집
- 메뉴 구성과 금액이 같은 주문이 몇 분 안에 또 들어오면 카드에 중복 의심 경고 표시
- 오늘 주문 수 · 오늘 매출을 상단에 항상 표시 (날짜가 바뀌면 자동으로 새로 집계)
- 번호표는 날짜가 바뀌면 001번부터 자동으로 다시 시작
- 부스에 붙일 QR 포스터를 화면에서 만들고 바로 인쇄
- **통계** 탭에서 날짜별 매출 · 메뉴별 판매량 · 결제 방법 비율을 막대그래프로 바로 확인
  (외부 차트 라이브러리 없이 직접 그린 SVG)

## 어떻게 만들어졌나

프레임워크도, 빌드 도구도 없습니다. 브라우저가 그대로 읽을 수 있는 HTML · CSS · JS 파일과
Supabase 프로젝트 하나가 전부입니다.

| 영역 | 사용한 것 |
|---|---|
| 화면 | 순수 HTML · CSS · JavaScript (ES 모듈), 외부 UI 라이브러리 없음 |
| 데이터 | [Supabase](https://supabase.com) — PostgreSQL + Auth + Realtime, 무료 플랜 |
| 실시간 갱신 | Supabase Realtime 구독, 놓치는 경우를 대비한 폴백 폴링 |
| QR 코드 생성 | `qrcodejs` (CDN) |
| 배포 | 정적 파일이라 아무 호스팅에나 올릴 수 있음 (아래는 Netlify 기준) |

별도 백엔드 서버는 없고, 그 역할을 Supabase의 **PostgreSQL 함수(RPC)** 와
**Row Level Security** 가 대신합니다. 손님이 주문을 넣으면 `place_order()` 함수가 그
순간의 메뉴 가격으로 합계를 다시 계산하고 번호를 발급하며, 손님은 자기 주문 하나만
`get_order()` 함수로 조회할 수 있습니다 — 그래서 다른 손님의 주문은 볼 수 없고, 금액도
클라이언트가 보낸 값을 신뢰하지 않습니다. 즉 "백엔드 코드"가 `sql/schema.sql` 파일 하나로
존재하는 구조입니다.

```
swi/
├─ index.html            손님용 — QR로 접속하는 메뉴 · 주문 화면
├─ gyomusil-7x4m.html    운영자용 "교무실" — 별도로 공유하는 관리자 주소
├─ css/
│  └─ style.css          칠판 · 공책 · 도장 콘셉트의 전체 디자인
├─ js/
│  ├─ store.js           데이터 창고 — Supabase 모드 / 데모(localStorage) 모드를 감춰서 제공
│  ├─ customer.js        손님 화면 로직
│  ├─ admin.js           관리자 화면 로직
│  └─ supabase-config.js 이 프로젝트가 연결할 Supabase 주소 · 키 (비어 있으면 데모 모드)
└─ sql/
   ├─ schema.sql         테이블 · 보안 규칙 · 주문 처리 함수
   └─ analysis.sql       매출 · 인기 메뉴 등을 뽑는 분석 쿼리 모음
```

각 JS 파일 맨 위에는 그 파일이 맡은 역할을 설명하는 주석이 있어서, 코드를 읽을 땐 거기서
시작하면 전체 구조가 잡힙니다.

---

## 설정 없이 먼저 열어보기

`js/supabase-config.js`의 값이 비어 있으면 자동으로 **데모 모드**로 동작합니다. 이 경우
주문은 그 브라우저의 localStorage에만 저장되기 때문에, Supabase 계정 없이도 `index.html`과
`gyomusil-7x4m.html`을 탭 두 개로 열어서 손님 · 운영자 양쪽 흐름을 그대로 체험해 볼 수
있습니다. (파일을 그냥 더블클릭하면 브라우저가 ES 모듈 로딩을 막을 수 있으니, VS Code의
Live Server 같은 로컬 서버로 열어야 합니다.)

## 다른 부스에서 그대로 쓰려면

### 1. Supabase 프로젝트 연결하기

1. [supabase.com](https://supabase.com)에서 새 프로젝트를 만듭니다. (Region은 Northeast
   Asia (Seoul) 권장)
2. **Authentication → Users** 에서 관리자로 쓸 계정을 하나 만듭니다 (Auto Confirm User
   체크).
3. `sql/schema.sql` 맨 아래에 있는 `'admin@example.com'`을 방금 만든 이메일로 바꾸고,
   Supabase의 **SQL Editor** 에 전체 내용을 붙여넣어 실행합니다. 테이블 · 보안 규칙 ·
   기본 메뉴가 한 번에 만들어집니다. (이미 데이터가 있는 프로젝트에 다시 실행해도
   안전합니다 — 테이블은 없을 때만 만들고, 함수만 최신 버전으로 교체됩니다.)
4. **Project Settings → API** 에서 Project URL과 anon public 키(`sb_publishable_…`)를
   복사해 `js/supabase-config.js`에 넣습니다. `service_role` 키는 손님 화면에 그대로
   노출되므로 절대 넣지 않습니다.

### 2. 배포하기

정적 파일이라 어디에 올려도 되지만, 계정 없이 가장 빠른 방법은 [Netlify
Drop](https://app.netlify.com/drop)에 `swi` 폴더를 통째로 끌어다 놓는 것입니다. 생성된
주소가 손님용이고, 그 뒤에 `/gyomusil-7x4m.html`을 붙인 주소가 관리자용입니다.

### 3. 메뉴 채우기

배포된 사이트를 처음 여는 순간엔 데모용 기본 메뉴만 들어 있습니다. 관리자 화면의
**메뉴 · 가격** 탭에서 이름 · 교시 · 설명 · 가격을 직접 채우면 되고, 시즈닝처럼 옵션을
골라야 하는 메뉴는 "옵션" 칸에 쉼표로 구분해서 적으면 손님 화면에 옵션별 담기 버튼이
자동으로 생깁니다.

## 축제가 끝난 뒤

모든 주문은 Supabase(PostgreSQL)에 그대로 남기 때문에, `sql/analysis.sql`에 준비된
쿼리로 매출 · 인기 메뉴 · 바쁜 시간대 · 취소율 같은 걸 바로 뽑아볼 수 있습니다.

| 쿼리 | 알 수 있는 것 |
|---|---|
| 1 | 날짜별 매출 · 주문 수 |
| 2 | 메뉴별 판매량 · 매출 비중 |
| 3 | 첫째 날 vs 둘째 날 메뉴별 판매 |
| 4 | 30분 단위 바쁜 시간대 |
| 5 | 계좌이체 / 현금 비율 |
| 6 | 주문 → 호출까지 평균 대기 시간 |
| 7 | 평균 주문 금액 (객단가) |
| 8 | 같이 많이 시킨 메뉴 조합 |
| 9 | 취소율 |

엑셀로 옮기고 싶다면 Supabase의 Table Editor에서 표를 열고 Export → CSV로 내보내면 됩니다.

핵심 테이블은 다음과 같이 나뉩니다.

| 테이블 | 내용 |
|---|---|
| `menu` | 메뉴 이름 · 분류(교시) · 설명 · 가격 · 품절 여부 · 시즈닝 옵션 |
| `settings` | 영업 on/off, 공지, 입금 계좌 |
| `orders` | 주문 한 건 — 번호, 결제 방법, 합계, 상태, 각 단계별 시각 |
| `order_items` | 주문에 담긴 메뉴 한 줄씩 — 주문 당시 이름 · 가격 · 개수 · 고른 옵션 |
| `counters` | 번호표 카운터 (날짜가 바뀌면 자동으로 리셋) |
| `admins` | 관리자로 인정할 이메일 목록 |

## 알아두면 좋은 점

- 금액은 손님 폰이 아니라 서버(DB)에 저장된 메뉴 가격으로 계산되므로 조작이 불가능합니다.
- 무료 Supabase 프로젝트는 7일 동안 아무 요청이 없으면 자동으로 일시정지됩니다. 축제
  전에 미리 만들어 뒀다면, 당일 전에 대시보드에 들어가 살아있는지 한 번 확인하는 게
  좋습니다.
- 관리자 주소는 추측하기 어려운 이름으로 되어 있고 손님 화면 어디에도 링크가 없지만,
  그 자체로 접근을 막는 건 아닙니다. 실제 데이터 보호는 Supabase Auth 로그인과
  `admins` 표 확인(RLS)이 담당합니다.
